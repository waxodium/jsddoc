# Contributing

Contributions to JSDDoc and its test suites are welcome. You can also contribute to the official JSMM compiler.

## Where to Contribute

Choose the repository that matches your contribution:

- **JSDDoc (this repository):** Documentation, examples, test suites, and related improvements.
- **JSMM (official compiler):** Compiler implementation, bug fixes, and feature development. Visit the [JSMM repository](https://github.com/waxodium/jsmm).

## Reporting Issues

The Legitimate repo is located in github. So we use Github Issues tag: 

- `feat`: For feature request or adding new concepts 
- `issue`: For reporting issues or difficulty
- `remove`: For features or concepts removal request. Optionally you can follow after with your chosen alternate concepts to replace or a complete removal with none by showing the issues or difficulty. 

Before opening an issue:

1. Check the documentation and existing issues.
2. Verify that the issue is reproducible.
3. Provide relevant details, including reproduction steps, expected behavior, actual behavior, and environment information.

**Do not report security vulnerabilities publicly.** Report them through the project's designated private security reporting channel.

## Suggesting Improvements

Before proposing an improvement:

1. Check whether it already exists or has been suggested.
2. Explain the proposed change and its motivation.
3. Describe its expected benefits and, where relevant, provide examples.

Submit suggestions to the repository most relevant to the proposal.

## Submitting Contributions

1. Fork the appropriate repository.
2. Create a branch for your changes.
3. Make and test your changes.
4. Submit a pull request describing what changed and why.

For compiler changes, follow the contribution guidelines in the [JSMM repository](https://github.com/waxodium/jsmm).

## Contribution Guidelines

- Keep changes focused and consistent with the project's scope.
- Write clear documentation and meaningful commit messages.
- Add or update tests when appropriate.
- Ensure your contributions are original or that you have the necessary rights to submit them under the project's license.
- Write language examples in a visual markdown JS codeblock, or take a screenshot of your code-snippets and submit the report.
